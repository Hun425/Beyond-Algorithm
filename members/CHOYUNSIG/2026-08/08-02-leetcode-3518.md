## [Smallest Palindromic Rearrangement II](https://leetcode.com/problems/smallest-palindromic-rearrangement-ii/)

### 접근 방법

3517번에서 $k$번째로 작은 문자열이라는 조건이 붙은 문제이다. 3517번에서처럼 앞 절반 문자열만 결정하도록 하여 답을 찾는다는 매커니즘은 똑같다.

가능한 모든 문자열의 개수가 $O(n!)$ 범위에 있으므로 완전 탐색은 불가하지만, $k$의 범위가 10의 6제곱이므로 $k$의 범위 내로 탐색을 시도하도록 하면 해결된다.

어떻게 해당 범위 안에서 탐색을 수행할 지에 대한 아이디어는 다음과 같다.
> 앞 글자부터 하나씩 확정해보면서, 뒤 문자열로 가능한 개수를 계산한다.

직관적이지 않아서 이해가 어려운데, 알파벳 대신 숫자로 바꿔서 이해해보자.

#### 뒷 문자열 조합 개수 계산 최적화

특정 자리의 문자를 확정하고 나서 가능한 뒷 문자열 조합의 개수를 계산해야 한다.
뒷 문자열의 길이를 $n$개, 그리고 남아있는 알파벳이 `a`는 $x_a$개, `b`는 $x_b$개, ..., `z`는 $x_z$개 남았다고 해보자.

먼저 `a`가 들어갈 자리부터 고른다. 이 경우의 수는 $\binom{n}{x_a}$이다. 그 다음 남은 자리에서 `b`가 들어갈 자리를 고른다. 이 경우의 수는 $\binom{n - x_a}{x_b}$이다. 그런 다음 `c`가 들어갈 자리를 고르면 이 경우의 수는 $\binom{n - x_a - x_b}{x_c}$이다. 이것을 계속 반복해 `z`까지 한다고 하자. 결국 뒷 문자열로 가능한 모든 문자열의 조합 수는 이것들을 모두 곱한 값이다.
> $\prod_{i}{\binom{n - \sum_{k}^{i - 1}{x_k}}{x_i}}$

조합 계산 시 팩토리얼 때문에 오버플로우가 날 수 있는데, 어차피 문제에서 주어지는 $k$값 너머로의 순번은 필요 없으므로 $k$ 값을 넘기는 즉시 계산을 하지 않도록 만들어주면 된다. 이것을 이용하기 위해 위 수식대로 곱을 계산하는 매 반복마다 값이 항상 커지기만 하도록 구성하여야 한다.

### 코드

```kotlin
import kotlin.math.min

class Solution {
    companion object {
        private const val A = 'a'
        private const val ALPHABET_SIZE = 26
    }

    fun smallestPalindrome(s: String, k: Int): String {
        val letterCounts = List(ALPHABET_SIZE) { 0 }.toMutableList()

        s.forEach { letter ->
            letterCounts[letter.code - A.code] += 1
        }

        val letterIndexOfOddCount = letterCounts.withIndex().singleOrNull { (it.value and 1) == 1 }?.index

        val result = letterCounts.map { count -> count / 2 }.runCatching {
            getKthLexicographicallySmallest(this, k)
        }.map {
            val middle = letterIndexOfOddCount?.let { Char(A.code + letterIndexOfOddCount) } ?: ""
            it + middle + it.reversed()
        }.getOrDefault("")

        return result
    }

    private fun getKthLexicographicallySmallest(letterCounts: List<Int>, k: Int): String {
        val remainLetterCounts = letterCounts.toMutableList()
        val result = mutableListOf<Char>()
        var sumOfPossibleString = 0L

        while (remainLetterCounts.sum() > 0) run {
            for (index in 0..<ALPHABET_SIZE) {
                if (remainLetterCounts[index] == 0) {
                    continue
                }

                remainLetterCounts[index] -= 1

                val countOfPossibleString = runCatching {
                    getCountOfPossibleString(remainLetterCounts, k)
                }.getOrDefault(k + 1)

                if (sumOfPossibleString + countOfPossibleString >= k) {
                    result += Char(A.code + index)
                    return@run
                }

                sumOfPossibleString += countOfPossibleString
                remainLetterCounts[index] += 1
            }

            throw IllegalArgumentException("no kth string")
        }

        return result.joinToString("")
    }

    private fun getCountOfPossibleString(letterCounts: List<Int>, limit: Int): Int {
        var result = 1L
        var n = letterCounts.sum()

        for (count in letterCounts) {
            result *= comb(n, count, limit)

            if (result > limit) {
                throw ArithmeticException("too many letters")
            }

            n -= count
        }

        return result.toInt()
    }

    private fun comb(n: Int, m: Int, limit: Int): Int {
        var result = 1L

        repeat(min(m, n - m)) {
            result *= (n - it)
            result /= (it + 1)

            if (result > limit) {
                throw ArithmeticException("too big number")
            }
        }

        return result.toInt()
    }
}
```

### 복잡도

- 시간복잡도: 매 $n$번마다 조합 계산을 하되 $k$ 제약 안에서만 수행하므로, $O(n \times \text{min}(n, \log{k}))$ (문자열 세트의 크기는 상수 취급)
- 공간복잡도: 입력에 의해 $O(n)$
